# AGENTS.md

Standing orders for this repository. The product contract lives in [README.zh.md](README.zh.md) / [README.md](README.md); these rules govern how the repo is changed.

## Layout

- `src/` — TypeScript source. `src/proxy.ts` is the pure-node proxy core (native Basic Auth gate, HTTP + WebSocket forwarding, Host/Origin alignment, polyfill injection) with **no cordis dependency**; `src/controller.ts` is the proxy controller (effective options = cordis base + persisted overlay, start/stop/restart, status/update/start/stop verbs, persistence to the profile-scoped state dir resolved by `src/state-dir.ts`); `src/state-dir.ts` derives `$DSH_HOME/profiles/<name>/dsh-proxy/` from `ctx.baseUrl`, falls back to the shared home on any parse failure, and seeds legacy home-root files once; `src/state-file.ts` is the unified YAML state IO (atomic writes, tolerant reads, one-time legacy JSON migration) used by all three config files; `src/index.ts` is the cordis plugin entry (Config schema incl. `stateScope`, effect lifecycle, the `/api/dsh-proxy` exact route on Connection's shared `/api` channel); `src/auth.ts` is the login gate's core (server-held sessions, per-source throttling, audit events — no HTTP), `src/audit.ts` the append-only trail, `src/security.ts` the persisted transport policy, `src/loginpage.ts` the self-contained login form (with a STATIC popup script only when OAuth channels are enabled), `src/oauth/finish.ts` the popup result page that notifies the opener over a same-origin BroadcastChannel, and `src/netaccess.ts` the access-mode/forwarded-header rule; `src/session.ts` / `src/settings.ts` / `src/contract.ts` are pure, unit-tested helpers and the shared wire contract; `src/polyfill.ts` is the randomUUID shim; `src/client/` is the browser half: the settings section (`SettingsSection.tsx`), the frame-wide per-page-load exposure notice (`LanExposureNotice.tsx`, registered into the shared `shell.overlay` seat), plus locales, styles, transport, and the plugin body. Authentication is a login page with a server-side session cookie (TLS, loopback, and cleartext by default), with the native Basic dialog as an explicit `cleartextAuth: 'basic'` alternative (see the access-mode rule below). `src/oauth/` is the third-party login layer: official endpoint table, unified auth-center overrides, one-shot state/PKCE, the manual binding table, and the runtime that answers `/__dsh-proxy/oauth/*`. A per-channel `providerHint` is appended as `provider_hint` to the authorize URL only when non-blank, so official endpoints stay byte-for-byte unchanged.
- `lib/` — committed build artifacts. `lib/index.cjs` is the fully self-contained host bundle the profile loads (schemastery, http-proxy, dsh-home-paths bundled inline; `@deepseek-ai/cordis` is type-only); `lib/client.js` is the browser bundle served at `/plugins/dsh-proxy/client.js` (only react is external). **Every source change that should be installable must rebuild and commit `lib/` in the same commit.**
- **Security posture (do not silently change):** the listener is bound exactly as configured, credentials or not — "reachable means the Basic Auth dialog, or straight in while the pair is unset". The hardening is **warning, not blocking**: `contract.ts`'s `isLanExposed()` (listener up + non-loopback host + auth off) drives the startup SECURITY WARNING, the red "open LAN access" badge and notice in the settings section, and `status.lanExposed`. A loopback-only bind and a stopped service must NOT be flagged. Turning this into a refused or degraded bind is a product decision, not a cleanup. The browser half mirrors the same rule through `status.lanExposed`: the notice is additive in `shell.overlay`, must stay non-modal (only its own card takes pointer events), and must ask the status endpoint at most once per page load. Dismissal is deliberately **not persistent** (no localStorage, no "already seen" state): the notice must return on every page load while the exposure lasts, because any remembered acknowledgement — permanent or per-day — mutes a standing security exposure. Do not add one.
- **Access modes (do not collapse them):** `netaccess.ts` resolves per-request — TLS (a trusted peer's `X-Forwarded-Proto: https`) or a loopback browser gets the **login page with a `__Host-`+`Secure` cookie**; a plain-HTTP LAN IP gets the **same login page by default** (`cleartextAuth: 'login'`) with the weaker non-`Secure` cookie variant, or the **native Basic dialog** when the operator sets `cleartextAuth: 'basic'` (a supported choice, never a silent fallback); cleartext is refused outright only under `requireTls`. The weaker cleartext cookie must stay visible: the settings card warns and the controller logs a SECURITY NOTE. Forwarded headers are believed ONLY from loopback or configured `trustedProxies` (the throttle keys on that address, so trusting them blindly would make it bypassable). A password-free configuration keeps the open behaviour: no gate, never a login form nobody can satisfy. With NEITHER a local password pair nor an enabled OAuth provider the open/warning posture stays (D2′): no login entry is rendered and every OAuth route is refused; with OAuth as the only method the gate turns on, and Basic credentials are accepted ONLY when a local password pair exists (otherwise `Authenticator.isAuthenticated()` would bypass an OAuth-only gate).
- **Callback origin is dynamic, never hardcoded:** `src/netaccess.ts` MUST keep two separate notions apart — `transportSecure` (did the browser actually connect over TLS? decides the `gate.origin` URL SCHEME) and `secureContext` (will a `__Host-`+`Secure` cookie be stored? loopback `http://127.0.0.1` counts). Conflating them makes `resolveGate()` emit `https://127.0.0.1:3081` and Casdoor redirects to a plain-HTTP port (ERR_SSL_PROTOCOL_ERROR). `OAuthRuntime.handle()` builds `redirect_uri` from `gate.origin` (the current request's Host + real scheme) so the callback host/port follows the page the browser used; an explicit `publicOrigin` override wins for reverse proxies. For the settings page (which runs on the DSH app's own port), `src/oauth/origin.ts` derives a DISPLAY origin from the RPC request's `Origin` / `Referer` / URL / Host server-side — never from a client-supplied hint that could redirect a binding ticket elsewhere — and substitutes the proxy's real port. Precedence: configured `publicOrigin` > request origin > legacy LAN-IP inference.
- **Login gate discipline:** sessions live in memory (a restart drops them) and the raw token never crosses the wire contract (`listSessions` projects a short id); login failures are uniform (no username/password distinction, constant-time compare) and throttled per source, and the audit trail records events WITHOUT credentials.
- `tests/` — vitest suites at the repo root, importing internals by relative path (`../src/*.ts`; the section spec is jsdom).
- `scripts/smoke.mjs` — live smoke test against a running DSH (`pnpm run smoke`), including a plugin-contract phase that drives the bundled `apply()` with a fake ctx (redirecting `$DSH_HOME` to a temp dir and anchoring `baseUrl` at a temp `profiles/web` profile, so the real persisted config is never touched); not part of `pnpm run check`.

- **Per-profile state (do not collapse):** the four persisted files (`dsh-proxy.yaml`, `dsh-proxy-audit.jsonl`, `dsh-proxy-security.yaml`, `dsh-proxy-oauth.yaml` — the third-party login overlay + manual binding table) live in `$DSH_HOME/profiles/<name>/dsh-proxy/` by default, so profiles never overwrite each other's port/credentials/audit trail; `stateScope: 'home'` is the explicit opt-out for the legacy shared files. All paths come from `resolveStateDir()` — do not hardcode `dshHomePath('dsh-proxy.yaml')` again. A `baseUrl` parse failure degrades to the shared home WITH a warning and must never break plugin load. Legacy files are copied once (never moved or deleted), only while the private dir has no state file, so an upgrade cannot lose saved credentials.
- **Config files are YAML (do not revert to JSON):** the three CONFIG files are read/written only through `src/state-file.ts` (`yaml` package, atomic temp + rename). `readStateYaml()` parses YAML, falls back to a legacy `.json` file and migrates it once (writing the YAML successor, keeping the old file for rollback), then to the caller's fallback; every caller passes a tolerant `normalize`. `seedLegacyState()` converts legacy home-root JSON into YAML on the way into the private dir. The audit trail stays `dsh-proxy-audit.jsonl`: it is an append-only event stream, not a config — one self-contained JSON line per event lets a torn tail be skipped; do not turn it into a YAML document. YAML 1.2 is a JSON superset, so hand-written JSON in a `.yaml` file still parses.

## Build and checks

- `pnpm run typecheck`, `pnpm run test`, `pnpm run build` — all three must be green before a commit claims completion; `pnpm run check` runs them in order.
- The bundle is CommonJS on purpose: http-proxy uses dynamic `require()` calls that esbuild cannot inline into ESM output. Keep `format: 'cjs'` and the `.cjs` extension.
- The cordis loader resolves the plugin by package name through the profile's node_modules and accepts the CJS shape (`unwrapExports`); the `dsh.bundle.patch` manifest key is what makes `dsh plugin add` register the bundle.

## Commit discipline

- Conventional commits (`feat:`, `fix:`, `docs:`, `test:`, `build:`, `chore:`) with a body explaining what and why for non-trivial changes.
- One concern per commit: proxy behavior, auth, docs, build tooling, and test fixes land separately.
- Never commit credentials, `node_modules/`, or logs.

## Integration

- This plugin is named `dsh-proxy` (matching the repository) and its source lives in the `dsh-proxy/` subdirectory of the dsh-proxy repository. The repo ROOT carries a thin package manifest (name `dsh-proxy`) so the plugin installs from the repository itself: online `dsh plugin --profile <name> add github:stack-brain/dsh-proxy#master` (recommended) or local `dsh plugin --profile <name> add file:C:/mydata/codes/dsh-proxy` (bundle route); changes take effect on the **next `dsh web` restart**.
- Dev type sources come from the npm registry, pinned to the versions the current harness (`@deepseek-ai/dsh@0.1.5-rc.1`) ships internally: `@deepseek-ai/cordis@^4.0.2`, `@deepseek-ai/schemastery@^3.18.2`, the `@deepseek-ai/dsh-*` packages at exact `0.1.5-rc.2` (`@deepseek-ai/dsh-client-runtime` at `0.1.1-rc.2`, its newest published line; `@deepseek-ai/dsh-client-ui-layout` is type-only and exists to declare the `shell.overlay` seat). When the harness version moves, bump these to the new harness's bundled versions and re-run `pnpm install` to fix API drift.
- The upstream port defaults to `ctx.webServer.port` (the web app's real bound port) when `upstreamPort` is 0; the plugin injects `webServer` so that value is always available before `apply` runs.
- Listen failures (e.g. EADDRINUSE when another dsh-proxy holds 3081) are logged loudly but must **never** fail the web app's boot.
